# サンプルアカウント投入リスト（KOTOI）

デモ用アカウントに「自然な思考の束」を作るための投入台本です。  
**コピペ用本文はそのままキャプチャ欄へ。** 1件ずつ投入し、分類・要約が落ち着いてから次へ。

想定ペルソナ: 個人事業／少人数開発の人。仕事の速さと学びを気にしていて、ときどき感情メモも残す。

---

## 使い方

1. サンプル専用アカウントでログイン（本番の自分用と分ける）
2. 下の **バッチ順** で投入（同じ日に全部やらず、A→B→C のあいだに少し待つと探究がきれい）
3. 探究が立つまで「探究をまとめる」相当の操作があれば実行
4. 問いの棚・地図・見取り図を確認
5. 見取り図は 1 枚目無料枠のデモに使える

動画は文字起こしできる公開 YouTube を選んでいます。取れない場合は「学びメモ」テキストだけ残しても成立します。

---

## 狙う探究の束（できあがりのイメージ）

| 仮の束名 | 中心テーマ | 主な投入 |
|---|---|---|
| 速さの正体 | 判断・情報・少人数 | バッチ A |
| 学べる速さ | 先延ばし・最初の20時間・記憶 | バッチ B |
| 道具と問い | AI・ツール・メモの使い方 | バッチ C |
| （単発） | feeling / task | バッチ D（問い少なめ・ノイズ） |

## バッチ A — 仕事の速さ・判断（seed / learn）

### A1（seed）
```
少人数で速いチームは、情報が足りないのではなく、
「誰が決めてよいか」が曖昧なときに遅くなる気がする。
```

### A2（seed）
```
レビュー待ちが長いとき、問題はレビューアの忙しさより、
「何を見てほしいか」が書かれていない側にあることが多い。
```

### A3（動画・learn）
```
https://www.youtube.com/watch?v=u4ZoJKF_VuA
スタートウィズ・ホワイ（Simon Sinek）。「なぜ」が先、の話としてメモ。
自分のプロダクトだと「問いを返す」が Why になっているか確認したい。
```

### A4（seed）
```
会議を減らすより、会議の前後に「決めたこと／決めないこと」を
3行で残す方が効く。残さないと翌週また同じ話をする。
```

### A5（learn・テキスト）
```
読んだメモ：権限と情報はセットで渡す。片方だけだと質問ラッシュか、沈黙かの両極端になる。
自分のチームで「権限だけ渡してコンテキストを渡していない」箇所はどこか。
```

### A6（seed）
```
速さを「個人の才能」にすると再現できない。
速さを「通り道の設計」にすると、弱い日でも破綻しにくい。
```

## バッチ B — 学習・先延ばし（learn / seed）

### B1（動画・learn）
```
https://www.youtube.com/watch?v=arj7oStGLkU
先延ばしのTED（Tim Urban）。Instant gratification monkey の比喩が刺さった。
「計画の自分」と「やる瞬間の自分」が別人格、という整理は自分のリリース前にもある。
```

### B2（動画・learn）
```
https://www.youtube.com/watch?v=5MgBikgcWnY
最初の20時間で何でもそこそこになる、という話。
完璧に学ぶ前に「恥ずかしい練習」を先に置く、をアプリのチュートリアル設計にも転用できそう。
```

### B3（seed）
```
読書メモを取る時間がもったいない日がある。
あとで問いにできそうな一行だけ残す、というルールにしたら続きそう。
```

### B4（seed）
```
「理解した」と感じる瞬間と、「使える」瞬間は別。
后者は小さなアウトプットがあるまで来ない。
```

### B5（learn・テキスト）
```
間隔反復の話を読んだ。同じ問いを週次で呼び戻すのは、記憶というより
「未解決のまま置いておく許可」に近い使い方もありそう。
KOTOIの呼び戻しと繋げて考える。
```

## バッチ C — AI・道具・メモ（seed / learn）

### C1（seed）
```
AIに丸投げすると速いが、問いが浅い。
自分の言葉で一度置いてから渡すと、返ってくる問いの解像度が上がる気がする。
```

### C2（seed）
```
ツールを増やすほど「どれを開くか」で疲れる。
入り口は一つ、奥で分岐、が理想。
```

### C3（動画・learn）
```
https://www.youtube.com/watch?v=eIho2S0ZahI
話し方のTED（Julian Treasure）。聞く気になる声の条件。
メモアプリだと「読まれる文」の条件に近い。短く、一意で、ノイズを減らす。
```

### C4（seed）
```
調べる前に仮説を一文書く癖をつける。
仮説がない調査は、あとで何を確かめたかったか忘れる。
```

### C5（learn・記事URL）
```
https://paulgraham.com/ds.html
Do things that don't scale。初期の手作業が製品の核になる、という話。
サンプルアカウントに手でメモを積み上げるのも、まさにそれ。
```
（記事本文を読みにいき、要約・問いが付く想定）

### C6（seed）
```
「完璧なナレッジベース」を目指すと更新が止まる。
雑多に放り込んで、あとから束ねる方が現実的。それがKOTOIの仮説でもある。
```

## バッチ D — feeling / task / ref（ノイズと配慮）

問い生成やクラスタの「人間味」用。feeling は掘りすぎない想定。

### D1（feeling）
```
眠れない夜。悪いことがあったわけではないのに、頭だけ忙しい。
明日に残すなら「今日はここまで」と言える線を引きたい。
```

### D2（feeling）
```
先週より少し楽だった。理由はよくわからない。天気だけかもしれない。
```

### D3（task）
```
請求書を送る。金曜まで。
```

### D4（task）
```
洗剤買う。冷蔵庫の詰替えも。
```

### D5（ref・保存だけ）
```
後で読む: 「認知負荷とUI」のノート用リンク置き場
https://www.nngroup.com/articles/minimize-cognitive-load/
```

### D6（seed・軽い）
```
散歩中に思いついた：問いが貯まると安心する人と、圧になる人がいる。
自分は前者寄り。棚は「圧」にならない見せ方が要る。
```

## バッチ E — 追加の動画枠（足りなければ）

文字起こしが取れ、テーマを広げたいとき。

### E1
```
https://www.youtube.com/watch?v=vKA4w2O61Xo
Veritasium「The Illusion of Truth」。繰り返すと信じやすくなる、という話。
メモや問いを「呼び戻す」とき、確認なしに真実化しないための注意にもなる。
```

### E2
```
好きな長尺の解説・講演を1本足すなら、再生できる公開URLの下に
「持ち帰りたい仮説」を日本語で2行書く。要約と問いが安定しやすい。
```

> 動画URLは投入前に端末で再生できるか確認してください。重要なのは **URL＋自分の一言** のセットです。

## 投入後チェックリスト

- [ ] ホームにルートメモが並ぶ（task は問いが少ない／ない）
- [ ] learn／動画に要約と問いが付く
- [ ] feeling に攻撃的な反証が来ていない
- [ ] 問いの棚に未回答が溜まる
- [ ] 探究が 2〜3 本立つ（立たなければ同じテーマをあと2件足す）
- [ ] 見取り図を1枚生成（無料枠 or Pro）
