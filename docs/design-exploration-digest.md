## 1. 消化のモデル（確定）

```
未整理の問いが溜まる
  → 「未整理が n 件」と見える
  → ユーザーが日常操作を押す（名前は R5）
  → AI は主に:
       A. 既存探究に足す（メンバー・切り口・synthesis を更新）
       B. 合わないものだけ新規探究
  → 探究 ID は維持
  → 変わった探究だけ見取り図を stale
```

二次操作: **「束を組み直す」**（フル再編・確認あり）。

---

## 2. 既存の束に入ったあとの体験（synthesis / 見取り図）

増分で既存探究に問いが入ると、だいたい次が動く:

| 変化 | ユーザーへの見せ方 |
|------|-------------------|
| 問い・切り口が増える | 地図・リストに自然に反映 |
| **synthesis（この束が示唆すること）** | **新しい文に差し替え**（増分の成果そのもの） |
| **見取り図** | 画像は残す。状態を **stale** に |

### トーン

- synthesis は「いまの束の説明」なので、**静かに更新してよい**（確認ダイアログ不要）
- 見取り図はコストと愛着があるので、**勝手に描き直さない**
- 促しは軽く: 「見取り図を更新できます」程度（合意）

### stale のときの UI（推奨）

**一覧カード**

```
見取り図
[画像は薄く／枠はそのまま]
見取り図を更新できます          [ 更新 ]  ← 際立たせる
```

**詳細ページ**

```
見取り図                    [更新]  ← ヘッダー右。通常の refresh より目立つ
（薄くした現行画像）
見取り図を更新できます。束の内容が変わっています。
```

| 状態 | 更新コントロール |
|------|------------------|
| `done`（最新） | 小さな refresh アイコン（今どおり控えめ） |
| **`stale`** | **「更新」ボタン or 強調アイコン**（色・サイズで際立たせる） |
| `pending` | 作成中枠（既存） |

「更新」を押す = いまの見取り図生成フロー（非同期・2〜3分・プッシュ）。  
押し直し前に **現行画像をアーカイブに残すか** は §4。

## 3. R5 — 操作名（再検討）

「新しい問いを束ねる」は、**新しい問い同士で新束を作る**ように聞こえるリスクあり → 不採用。

### 候補

| 案 | 伝わること | 懸念 |
|----|-----------|------|
| **A. 新しい問いを振り分ける** | 既存の棚／束への割り当て | 「振り分け」が事務的・やや硬い |
| **B. 未整理の問いを載せる** | 未整理 → 探究へ | 「載せる」がやや曖昧 |
| **C. 問いを探究に入れる** | 行き先が探究だと明確 | 新規探究作成が伝わりにくい |
| **D. 未整理を探究へ** | 短い・状態起点 | 動詞が弱い |
| **E. 探究に取り込む** | 増分吸収 | 「何を」がボタンだけだと弱い |

**推奨: A「新しい問いを振り分ける」**  
- 既存束への割り当てが主、余りは新規、というモデルと一致  
- 補足コピーで補う: 「未整理の問いが 4 件あります。既存の探究に足すか、新しい探究を立てます。」

二次操作は据え置き: **「束を組み直す」**

**R5 は合意済み**（「新しい問いを振り分ける」）。

## 4. 見取り図 — 消える／残る／保存（前提の確定）

前回の「アーカイブに残す」「組み直し前に保存確認」は **撤回**。次の前提に置き換える。

### ケース別

| ケース | 見取り図どうなる | ユーザーへの案内 |
|--------|------------------|------------------|
| **新しい問いを振り分ける**（増分） | **現行の図はそのまま残る**。状態だけ `stale` | 「見取り図を更新できます」＋際立つ更新ボタン |
| **見取り図を再生成する**（stale 更新・手動更新） | **今の図は消える**（上書き） | **再生成前に案内** → 了解後に削除して生成開始 |
| **束を組み直す**（フル再編） | **探究ごと消えるので図も消える** | **全部消えることを確認** → OK なら消してよい（保存を強要しない） |

### 再生成前の案内（文言案）

> いまの見取り図は消えて、新しく描き直します。よろしいですか？  
> ［キャンセル］　［描き直す］

### 「保存」の位置づけ

- **アプリ内アーカイブや、振り分け／組み直し時の強い保存促しはしない**
- 見取り図は **図ごとに長押しで保存**（端末の写真／ファイルへ、OS の共有シート等）できれば十分
- ユーザーが残したいときだけ自分で保存する。プロダクト側は消えることを **事前に正直に言う** だけ

### 決めてほしかった S1 / S2 → 確定案

| 旧 | 新（確定） |
|----|-----------|
| S1 作り直し時に旧図を既定で残す | **残さない。消えることを案内してから削除** |
| S2 束を組み直す前に保存確認 | **「全て消える」確認のみ。保存は促さない** |
| （追加）任意保存 | **長押しで端末に保存**（強い導線なし） |

## 5. UI 骨格

```
似たメモと問いが束になって立ち上がったテーマ。3件が育っています。

（探究なし・未整理あり）
[ 新しい問いを振り分ける ]
  未整理の問いが 4 件あります

（探究あり・振り分け直後／その後あたらしい問いなし）
  探究は最新です
  （未整理が残っていてもよい）
  まだ束になっていない問いが n 件あります。
  あたらしい問いが生まれると、ここから探究の束になれることがあります。
  · 束を組み直す

（探究あり・振り分け後にあたらしい問いが増えた）
  あたらしい問いが増えています
  振り分けてから n 件の問いが加わっています。
  [ 新しい問いを振り分ける ]
  · 束を組み直す
```

未整理の残りは失敗ではない。メモが足りず束になれないだけなので、
「あたらしい問いを生む」方向へ促す。無理に全部は振り分けない。

振り分け後:

- synthesis は静かに更新
- stale: 「見取り図を更新できます」+ **際立つ更新**
- 更新タップ → **「いまの図は消えます」確認** → 非同期生成
- 完成済みの図: **長押しで保存**（いつでも可）

束を組み直す:

- 「探究と見取り図はすべて作り直されます。今の見取り図や探究の束を残したい場合は、個別に保存してください。」確認 → 実行
