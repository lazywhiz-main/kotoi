## 2. 本サービスの趣旨とデータの位置づけ

KOTOI は、ユーザーが投入したメモを AI が分類・要約し、「次の問い」を返す**個人用ノート**です。データの中核は次のとおりです。

| 区分 | 内容 |
|---|---|
| **インプット（ユーザーが渡すもの）** | メモ本文、URL、回答・追記、ログイン情報、通知許可時のプッシュトークン、課金手続情報（ストア側） |
| **処理（当方／委託先が行うこと）** | 分類、要約、文字起こし取得、問い生成、調査・深掘り、探究クラスタリング、見取り図画像生成、週次ふりかえり、利用量・購読状態の管理 |
| **アウトプット（ユーザーに戻るもの）** | 分類結果、要約、問い、調査結果、探究・地図、見取り図、ふりかえり、通知 |
| **保管（DB上の本人データ）** | 下記「5. 取得する情報」および「附录A」。原則として `user_id` 単位で隔離し、他ユーザーからは読めません |

本サービスは現状、**ユーザー同士のタイムライン共有や公開プロフィール機能を持ちません。** 見取り図などを OS の共有シートで外部に送る場合は、ユーザー自身の操作に基づきます。

## 4. 取得方法

1. **ユーザーが直接入力・操作した情報**（メモ、設定、ログイン等）
2. **サービス利用に伴い自動取得する情報**（端末種別の一部、プッシュトークン、利用量ログ、認証提供者から渡される識別子等）
3. **外部サービスから受け取る情報**（リンクのOGP、動画の文字起こしが取得できる場合のテキスト、購読状態の Webhook 等）

## 5. 取得する情報

### 5.1 アカウント・認証

- ユーザーID（内部UUID）
- メールアドレス（メールログイン、または Apple／Google が提供する場合）
- Apple／Google 等の外部認証に関する識別子・表示名（提供範囲に依存）
- パスワード（メール＋パスワード利用時。当方が平文で保持することはなく、認証基盤側で適切に管理）

### 5.2 ノート本文およびスレッド（中核コンテンツ）

- ルートメモの本文（`raw_text`）
- メモ種別（seed／learn／task／feeling／ref 等）、動画フラグ
- ソースURL、タイトル、サムネイルURL
- 動画タイトル、文字起こし本文およびその処理状態
- スレッド項目: 要約、問い、ユーザー追記、依頼、調査結果、回答 等の本文
- 問いの類型（深掘り／接続／反証／行動／拡張）、回答済み状態
- タグおよび分類訂正の履歴

### 5.3 探究・見取り図・ふりかえり

- 探究タイトル、短いラベル、統合文、進行度
- 探究とメモ／問いの対応関係
- 見取り図の生成状態、バリアント、保存パス、プロンプト版、選定理由、エラー情報、生成時刻
- 週次ふりかえり本文および関連メタデータ

### 5.4 通知・設定

- 通知設定（エージェント完了、週次ふりかえり等）
- 表示テーマ等の設定
- Expo Push Token およびプラットフォーム情報

### 5.5 利用量・課金

- AI呼び出し単位のトークン数・概算コスト等の利用台帳（日次上限・不正検知・品質改善のため）
- トライアル／到達状態、無料見取り図枠、プラン種別、学生フラグ（該当時）、ストア種別、期間情報、キャンセル時刻等の購読状態
- 課金プロバイダ（RevenueCat）および App Store／Google Play から連携される購読イベント（サンドボックス／本番を含む）

### 5.6 端末・アプリ上のローカル情報

- 前回ログイン方法の表示用情報、チュートリアル／オープニング演出の進行など、**端末ローカル**にのみ置く情報があります。これらはサーバーに送らない、または最小限にとどめます。

### 5.7 取得しない／現状扱わないもの

- 連絡先帳、精密な常時位置情報、マイク連続録音、カメラ常時アクセス等は、現行機能の必須ではありません（将来機能追加時は本ポリシーとストア申告を更新します）。
- 広告IDを用いた第三者広告トラッキングは行いません（現行方針）。

## 6. 利用目的

取得情報は、次の目的でのみ利用します。

1. 本サービスの提供（認証、保存、表示、AI処理、通知）
2. 利用上限・トライアル・有料プランの判定および不正防止
3. 障害対応、セキュリティ、サポート対応
4. サービス改善（プロンプト・分類品質の向上）。**学習目的でユーザー本文を第三者の基盤モデル一般学習に無断提供しない**方針とします（委託先の標準条件が異なる場合は契約・設定で可能な限り除外し、変更時は本ポリシーを更新します）
5. **利用状況の把握（Analytics）**: 画面の開閉、メモ作成の有無、問い・課金まわりの操作など、機能改善と障害把握のためのイベント記録。**メモ本文・問い本文・メールアドレス等は含めません。** 第三者の広告・行動分析 SDK は用いず、当方のサーバー（Supabase）上に保存します
6. 法令に基づく対応

## 7. 第三者提供・委託（処理の外注）

当方は、本サービス運営のため、次の類型の事業者に個人データ・コンテンツの処理を委託し、または必要な範囲で提供することがあります。

| 類型 | 想定例 | 主な扱い |
|---|---|---|
| クラウドDB／認証／ストレージ／Functions | Supabase 等 | アカウントおよび全ユーザーデータの保管・RLSによる本人隔離 |
| 言語モデルAPI | Anthropic 等 | 分類・要約・問い・調査・ふりかえり等の生成 |
| 画像生成API | OpenAI 等 | 見取り図画像の生成 |
| 課金状態管理 | RevenueCat、Apple、Google | 購入・更新・解約状態の同期（アプリユーザーIDとの紐づけ） |
| プッシュ配信 | Expo 等 | 完了通知等 |
| リンク／動画メタデータ取得 | 公開ウェブ、動画プラットフォーム由来の取得処理 | タイトル・サムネ・文字起こし等 |

これにより、データが日本国外で処理・保管される場合があります。当方は委託先の選定と契約・設定上の安全管理に努めます。

**販売目的での個人データの第三者提供は行いません。**

## 8. 安全管理

1. 通信は暗号化（HTTPS 等）を原則とします。
2. データベースは行単位のアクセス制御（Row Level Security）により、原則として本人のデータのみアクセス可能です。サーバー側の管理処理は権限を限定した実行環境で行います。
3. APIキー等の秘密情報はクライアントに置かず、サーバー側で管理します。
4. ただし、インターネット経由のサービスに絶対の安全はありません。ユーザー側でも端末ロック、OS更新、共有操作への注意をお願いします。

## 9. 保存期間

| データ | 目安 |
|---|---|
| アカウントおよびノート等の本体 | アカウント存続中。削除請求または退会後、合理的期間内に削除または匿名化 |
| 利用台帳・ログ | 不正対策・課金整合・障害調査に必要な期間（その後削除または集計のみ残す場合あり） |
| 購読状態 | 課金の証明・サポート・法令対応に必要な期間 |
| バックアップ | システム上のバックアップサイクルに従い、サイクル経過後に消滅 |

## 附录A — データ項目と主な保存場所（実装対応表）

本附录は、透明性のために現行データモデルを要約したものです。技術名・テーブル名はユーザー向け画面には現れません。

| 領域 | 主な項目（例） | 保存の中心 |
|---|---|---|
| 認証 | メール、外部ログイン識別子 | 認証基盤（Supabase Auth） |
| ルートメモ | 本文、種別、URL、文字起こし | `notes` |
| スレッド | 要約・問い・追記・依頼・結果・回答 | `thread_items` |
| 探究 | タイトル、統合、見取り図メタ・ストレージパス | `explorations` + Storage |
| 関連付け | 探究↔メモ／問い、メモ↔タグ | `exploration_*`, `note_tags`, `tags` |
| 利用量 | 関数名、トークン、概算コスト | `usage_ledger` |
| 分類フィードバック | 訂正前後の種別 | `classification_feedback` |
| 設定・通知 | 通知フラグ、プッシュトークン | `user_settings`, `push_tokens` |
| 購読 | trial_state、plan、期間、無料見取り図枠 | `subscriptions` |
| 週次 | ふりかえり成果物 | `weekly_reviews` |

**処理の流れ（概念）**

```
ユーザー入力（メモ／URL／回答／依頼）
  → アプリ（Expo）
  → バックエンド（Supabase + Edge Functions）
  → 必要に応じて AI／画像／外部取得 API
  → 結果を DB／Storage に保存
  → アプリに表示（＋任意でプッシュ通知）
課金イベント → RevenueCat Webhook → subscriptions 更新
```
