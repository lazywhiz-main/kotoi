# 設計メモ — リズムで届く「別角度の呼び戻し」

最終更新: 2026-07-10  
ステータス: **方針確定** → 実装計画 [`plan-scheduled-recall-question.md`](./plan-scheduled-recall-question.md)  
関連: 今週のふりかえりの「呼び戻し」、問いの棚、探究

---

## 1. 一言で

**目的は呼び戻し。手段は新しい角度。**  
眠っている問い・一言・探究に、ハッとする切り口で戻す。  
「呼び戻し vs 拡張」ではなく、**呼び戻すために別角度で問いかける**。

---

## 2. 既存の「呼び戻し」との違い

| | ふりかえり内の呼び戻し（既存） | 本企画 |
|--|-------------------------------|--------|
| 中身 | 数週間前の**未回答問いを再提示** | **新しい問いを1つ生成**（別角度） |
| タイミング | 週次ふりかえり生成時 | ユーザーが選んだリズム |
| 置き場 | ふりかえりカード内 | ホーム／棚など（後述） |
| ねらい | 「まだ生きてる？」と再掲 | 「この切り口で戻るとハッとする」 |

共存可。名前が被るので、UI では本企画を **「今日の問い」** または **「別角度」** と呼ぶ案（§6）。

---

## 3. 体験の骨格（合意）

```
溜まった問い・一言・探究
  → ユーザーが選んだリズムで発火
  → AI が「既存の何かに触れる別角度の1問」を生成
  → 静かに提示（ホーム先頭など）
  → ユーザーが開く／スルー／残す
```

### 良い問いの条件

- **錨がある**: どのメモ／どの未回答問い／どの探究に触れているか分かる
- **言い換えではない**: 同じ問いの再掲や薄いパラフレーズ禁止
- **ハッとする**: 前提をずらす・接続する・反証する・拡張する、いずれでもよい
- **類型は固定しない**: `exp` 寄りになりやすいが、`con` / `ref` / `dig` / `act` も可。本質は「別角度」
- **量は1問**（多くても2は例外。基本1）

### やらないこと

- 毎日複数問を自動で棚に積み増し
- 調べる／深掘りなど重い処理の自動実行
- 材料が薄いのに無理生成
- 汎用的で当たり障りのない問い

## 4. 論点と決定

### 確定（既定案を採用）

| # | 決定 |
|---|------|
| **T1** | 目的＝呼び戻し。手段＝新しい角度（VS ではない） |
| **T2** | **リズムはユーザー選択**（オフ／毎日／平日／週1 など） |
| **T3** | 置き場＝**ホーム先頭に1枚** |
| **T4** | 保存＝**提示 →「残す」**（勝手に増殖しない） |
| **T5** | 材料＝未回答＋一言を主。探究 synthesis は補助 |
| **T6** | 通知＝リズムに連動（オフならプッシュなし） |
| **T7** | 材料不足・直近スルー／残し直後はスキップ |
| **既定リズム** | **週1** |
| **時刻** | 朝 8:00（端末ローカル想定） |
| **名前** | カード「今日の問い」／設定「別角度の呼び戻し」 |
| **ふりかえり** | **分離**（俯瞰＋旧問い再掲とは別機能） |

### T2 選択肢（案）

| 値 | 意味 |
|----|------|
| オフ | 生成しない |
| 毎日 | 毎朝（時刻は共通設定） |
| 平日のみ | 月〜金 |
| 週1 | 曜日を選ぶ。ふりかえりと同日に揃えるオプション可 |

設定の置き場案: **設定 → 呼び戻し**（または通知セクション近く）。  
既存トグル「今週のふりかえり」とは別行。

## 5. UI ラフ

### ホーム

```
┌─────────────────────────────┐
│ 今日の問い · 別角度          │
│ 「〜〜〜？」                 │
│ ↳ ○○のメモ／問い に触れて   │
│          [開く]  [残す]  [×] │
└─────────────────────────────┘
（その下にいつものメモ一覧）
```

- **開く**: 錨のスレッドへ（問いがまだ無いならメモへ）
- **残す**: 錨ノートのスレッドに問いとして保存 → 棚にも載る
- **×／スルー**: 消える（しばらく再提示しない）

### 設定

```
呼び戻し（別角度）
  リズム  [オフ ▼]  毎日 / 平日 / 週1 / オフ
  週1のとき 曜日 [日 ▼]
  届いたら通知  [オン]   ※リズムがオフなら無効
```

### 空・スキップ時

カード自体を出さない（「今日はありません」と毎回言わない）。

## 6. 名前

| 候補 | 印象 |
|------|------|
| **今日の問い** | わかりやすい。毎日以外でも「今日」でよいか要検討 |
| **別角度** | 手段が伝わる。目的（呼び戻し）は弱い |
| **呼び戻し** | 既存ふりかえりと被る |
| **朝の問い** | 時刻前提が強い |

**推奨**: カード見出しは **「今日の問い」**、設定名は **「別角度の呼び戻し」**。  
週1の日も「今日の問い」でよい（その日届いた1問、の意味）。

---

## 7. ふりかえりとの関係

| 案 | 内容 | 評価 |
|----|------|------|
| **分離（推奨）** | ふりかえり＝俯瞰＋旧問い再掲。本機能＝別角度の新1問 | 役割がはっきり。リズムも独立 |
| 統合 | ふりかえり成果のひとつに「別角度1問」を含める | 週1利用者には楽だが、毎日勢と合わない |

週1に揃えた人向けに、後から「ふりかえりと同じ日に届ける」オプションを足せる。

## 8. AI・コスト（実装時の制約メモ）

- 軽処理のみ（1問 JSON）。research / dig は呼ばない
- `usage_ledger` 対象。日次上限に乗せる
- プロンプト原則: 錨必須・言い換え禁止・類型は内容に従う
- 出力例のイメージ:

```json
{
  "anchor": { "note_id": "...", "question_id": "..." },
  "question_type": "con",
  "body": "...",
  "why_now": "一言で、なぜこの切り口か（UIでは小さく可）"
}
```

- スケジュール実行は Edge の cron / scheduled function 想定（詳細は実装計画で）
