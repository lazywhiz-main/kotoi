# 08 — SNS投稿導線（開発仕様）

> **これは「あったら嬉しい機能」ではない。PLの紹介係数3.0（＝集客の主力）は、この実装を前提にしている。**
> 見取り図を外の SNS に出せなければ、成長ループ①は回らず、流入は自己発信の分だけになる。

ファイル名 `08_sharing.md` は履歴上のまま。中身の用語は **投稿** に統一する。

---

## 0. 用語（ここを正とする）

| 使う言葉 | 意味 | 使わない／避ける |
|---|---|---|
| **保存** | 自分の端末・アルバムに残す | 「シェアして保存」など混ぜた言い方 |
| **投稿** / **SNS投稿** | Instagram・X など**外の SNS** の投稿画面へ画像を渡す | **アプリ内シェア**（MONDO 内の他人へ渡す機能に聞こえる） |
| **投稿導線** | アプリ UI 上の「Instagram に投稿」などのボタン〜到達体験一式 | 「シェア機能」「共有ボタン」を曖昧に使うこと |
| **公開ページ（Web）** | 将来の `mondo.app/s/{token}`（一旦見送り） | 初期必須扱い |

### 保存と投稿は別体験（混ぜない）

| | **保存** | **投稿（SNS）** |
|---|---|---|
| 目的 | 自分の手元に残す | 外の SNS に出す |
| いまの実装 | 見取り図の**長押し** → OSシートで写真へ保存など | **未実装**（本仕様の本体） |
| 典型UI | 長押し／「保存」 | 「Instagram に投稿」などの明示ボタン |

OSのシート上で「写真に保存」と「アプリに送る」が並ぶことはあるが、**プロダクト上の動線・コピー・計測は分けて設計する。**

### 核となる体験

> **「Instagram に投稿」を押す → 生成画像が載った Instagram の投稿画面へ進む**

行き先が外の SNS であること。MONDO ユーザー同士の受け渡しではない。X 向けなども同系統。  
（実装手段は Instagram のシェア拡張・Stories pasteboard・OSシートで Instagram を選ばせる、など。到達体験が「投稿画面に画像が入っている」こと。）

## 1. 回したいループ

```
ユーザーが見取り図を SNS に投稿
  → 見た人が「何これ、きれい」「どうやって作ったの」
  → （将来）公開ページ or プロフィールの mondo.app → LP → インストール
  → 自分の見取り図ができる → また投稿
```

**見取り図は、MONDOが吐き出す広告素材である。** 手描き風なのでAI生成の見た目がせず、人文層のアレルギーを回避できている。この資産を外に出さない手はない。

初期は **画像投稿＋控えめウォーターマーク（mondo.app）** でループを回す。Web 公開ページは必須にしない（§5）。

|---|---|---|
| **見取り図** | 投稿用画像（用途別サイズ・WM） | **Instagram / X** ← 主力 |
| 問い | テキスト（画像化も可） | X |
| 探究まるごと | （将来）公開ページ | note・ブログでの引用 |

## 3. UI 上の投稿導線

### 見取り図の詳細画面

- **投稿ボタン**（例: 「Instagram に投稿」）。保存／長押し保存とは別。
- 押すと、**生成画像が載った投稿フロー**へ（理想は Instagram の投稿画面直結）。
- 必要なら X 用なども同型で足す。
- **初回だけ**、そっと促す: 「この1枚、誰かに見せますか？」——**1回だけ**。しつこくしない。
- 保存は既存どおり長押し（または明示の「保存」）。投稿の促しと同時に出さない。

### 問いのカード

- メニューから「この問いを投稿」など（文言は実装時に静かめに）
- テキストコピー ＋ 画像化オプション（ダークの美しいカード）

**注意**: 投稿を煽らない。ポップアップ・バッジ・催促は**禁止**。静かなトーンを壊した瞬間、この層は去る。

## 4. 画像出力の仕様

見取り図の元画像から、用途別に書き出す。

| 用途 | サイズ | 備考 |
|---|---|---|
| **Instagram（フィード）** | **1080 × 1350（4:5）** | 最大表示。上下に余白を足して見取り図を中央に |
| Instagram（正方形） | 1080 × 1080 | |
| **X** | 1200 × 675（16:9）or 元の1:1 | Xは1:1でもカード展開される |
| **OGP** | 1200 × 630 | 将来の公開ページ用 |
| 保存・印刷 | 元解像度 | 投稿用加工とは別パイプラインでも可 |

### ⚠️ 生成プロンプト側の要件 —「整えない」

**AI生成に見えないことが、この絵の最大の価値。** 完璧に整った瞬間、ただのAI画像に落ち、人文層のアレルギーを踏む。

`04_ai-prompts.md` の見取り図生成プロンプト（`generate-exploration-graphic-rec`）に、**意図的な不完全さ**を要件として入れる：

- 紙の質感、わずかな歪み、線のかすれ
- 定規で引いたような直線を避ける
- 手で描いた痕跡（にじみ、濃淡のムラ）

**「これ、本当に手で描いたの？」と訊かれる状態が正解。** 整えないことが機能である。

### ウォーターマーク

- **右下に、控えめに**。MONDOのシンボル ＋ `mondo.app`（小さく）
- 主張しない。**作品の邪魔をしない**のが絶対条件
- 有料ユーザーもウォーターマークは入る（＝これが広告なので）。ただし**設定でオフにできる**（作品として使いたい人がいる。そこを縛ると信用を失う）

## 5. 公開ページ（Web）— **一旦見送り／将来候補**

> **2026-07 判断: 初期スコープから外す。** 主戦場は画像の SNS 投稿（IG/X）。IG ではリンクが弱いので、まず絵＋WM（`mondo.app`）で回す。需要と計測の必要が見えてから着手。

将来やる場合の仕様メモ（捨てない）:

`https://mondo.app/s/{token}`

### 表示するもの

1. **見取り図**（大きく）
2. **元になったメモの抜粋**（1〜2本、短く）
3. **そこから立った問い**（2〜3個、5類型の色付き）
4. 「このメモから、MONDOがこの1枚を描きました」
5. **CTA**: 「あなたの探究も、1枚になる」→ ストアバッジ

**Before / After の構造**にする。放り込んだもの → 返ってきたもの。これが最も伝わる。

### 技術要件

- **OGP対応必須**（X・Instagram・Slackでカード展開される）
- 静的生成（速い）。認証不要
- `?ref={token}` で流入を計測

着手条件の目安: SNS 投稿が実際に起きている／note・ブログ・Slack で「リンクで渡したい」需要が明確／紹介係数を page view → install で測りたくなったとき。

## 6. プライバシー（人文層には、ここが決定的）

**デフォルトは完全非公開。** SNS に出した画像以外は外に出ない。公開ページを将来作る場合も、明示したものだけがリンクを知る人に見える。

- 公開は**トークン方式**（推測不可能なURL）
- **いつでも取り消せる**（`revoked_at`）。取り消したら404
- 公開ページに**表示する内容をユーザーが選べる**（見取り図だけ / メモも含める）
- 検索エンジンに載せない（`noindex`）。※Minaの公式運用分は例外的に許可
- **アカウント全体の公開設定は作らない**。1つずつ選ばせる

> この層のデータは「その人の思考の履歴」。うっかり公開される設計は、一発で信用を失う。

## 7. 計測（紹介係数の実測）

| イベント | 意味 |
|---|---|
| `sns_post_started` | 投稿導線を開いた（先・kind別） |
| `sns_post_image_ready` | 投稿用画像を書き出した |
| `public_page_viewed` | （将来）公開ページが見られた（ref付き） |
| `public_page_to_install` | （将来）公開ページ経由のインストール |

旧メモの `share_*` は公開ページ用の別名として §5 着手時に揃えてよい。

**PLの前提「紹介係数 3.0（有料1人が月3訪問を生む）」は、ここで検証する。** 実測が1.0を割ったら、集客モデルを組み直す必要がある。

## 8. 公式アカウント運用の支援機能（Minaの運用を楽にする）

Minaが自分でMONDOを使い、その探究をSNSに流す運用（→ SNS戦略 §10）を、**製品側から支援する**。

### 「探究をエクスポート」

探究の詳細画面から、**1タップで書き出せる**：

```
/exports/{exploration}/
  ├─ mitorizu-4x5.png      （Instagram フィード用・主力）
  ├─ mitorizu-1x1.png      （正方形）
  ├─ mitorizu-ogp.png      （X / OGP 用）
  └─ caption.txt           （1行キャプションの下書き：「今週読んだもの：〇〇」）
```

**シンプルに、絵だけ。** 問いも解説もカルーセルも出さない。

Instagramには**見取り図を1枚、1行のキャプションで置く**。説明しないことが、「これ何？」を生む。プロダクトの説明は、プロフィールと固定ハイライトが引き受ける。

**だからこそウォーターマークが重要になる。** Instagramではリンクが張れない以上、**絵の右下の `mondo.app` が実質のCTA**。控えめに、しかし必ず入れる。

この書き出しが1タップで終わることが、**週次運用の生命線**。手作業で画像を切り出す設計にすると、3週間で止まる。

## 9. データモデル（追加分）

初期の SNS 投稿だけなら `shares` テーブルは必須ではない（クライアント計測＋必要なら `usage`／独自イベントで足りる場合あり）。

公開ページ（§5）をやるときに足す:

```sql
create type share_kind as enum ('graphic','question','exploration');

create table shares (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid not null references auth.users(id) on delete cascade,
  kind        share_kind not null,
  target_id   uuid not null,                 -- exploration_id / thread_item_id 等
  token       text not null unique,          -- 推測不可能なランダム文字列
  include_notes boolean not null default false,
  view_count  int not null default 0,
  revoked_at  timestamptz,
  created_at  timestamptz not null default now()
);
create index shares_token_idx on shares (token) where revoked_at is null;

alter table shares enable row level security;
create policy own_shares on shares for all
  using (user_id = auth.uid()) with check (user_id = auth.uid());
-- 公開ページは Edge Function（service_role）が token で引く。RLS は通さない。
```

## 11. やらないこと（この仕様の範囲外）

- MONDO **アプリ内で他ユーザーに渡す**機能（フォロー・DM・公開プロフィール等）
- 保存と投稿の動線・コピー・計測を同一機能として扱うこと
- 投稿の催促・ゲーミフィケーション（バッジ、連続記録）
- 他人の見取り図を見るフィード
- アカウント全体の公開設定
- **初期の Web 公開ページ**（§5 に将来メモとして残す）
